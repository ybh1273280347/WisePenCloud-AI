# 2026-06-26

今天这轮工作的主线很集中：把搜索工具体系收干净，把学术搜索从隐式路由里拆出来，同时把 ranking tokenizer 也按新的要求收了一遍。

## 今天完成了什么

### 1. 把搜索工具里的隐式规划链拆掉了

今天最核心的改动，是把原来搜索工具内部那条“自动判断意图、自动挑 route、自动多跳搜索”的链路拆掉了。

已经去掉或禁用了这些行为：

- 小模型意图路由
- 内部 search route / provider endpoint 规划
- 自动 next query 生成
- 内部多跳搜索
- coverage-based retry
- hop merge

现在小模型只保留在候选选取、筛选、排序这一层，不再参与搜索规划。

### 2. 新增了显式 `academic_search` 工具

这次没有把学术搜索继续藏在 `web_search` 的内部 route 里，而是直接做成了独立工具：

- `academic_search`

这样工具语义更直接，模型看到的能力边界也更清楚。

### 3. academic_search 的暴露条件改成由 Exa 能力决定

今天把 academic_search 的工具暴露逻辑也接上了搜索凭证能力判断。

现在的规则是：

- 用户存在可用 Exa 凭证时，暴露 `academic_search`
- OpenAlex key 不影响 `academic_search` 是否暴露

同时，搜索凭证模型里补了能力字段和 OpenAlex 相关字段，后面如果再扩别的 provider，也还有复用空间。

### 4. 把 OpenAlex 收敛成 academic_search 的可选水合来源

OpenAlex 现在只做一件事：

- 对 Exa 学术搜索结果做可选水合

今天把这条链收成了比较克制的实现：

- 先用 Exa 搜候选
- 只基于 Exa 返回的 `title` 和 `url` 做 OpenAlex 匹配
- 优先按 `url` 匹配
- `url` 失败再按 `title` 匹配
- 如果出现多个候选，直接放弃水合
- 如果没有匹配上，也直接静默退回 Exa 结果

最终暴露给模型的 OpenAlex 字段也已经收窄到：

- `doi`
- `publication_year`
- `cited_by_count`
- `authors`
- `institutions`
- `open_access`

没有再把大体积原始对象往外透。

### 5. academic_search 的最终 URL 接进了现有 search URL 映射缓存

今天还把 academic_search 的 URL 返回逻辑接回了现有 search 缓存体系，没有另起一套独立映射。

现在行为是：

- 没有水合时，缓存 Exa URL
- OpenAlex 水合成功且有更合适 URL 时，缓存 OpenAlex URL
- 后续 `web_fetch` 可以继续用已有 candidate id 解析到最终 URL

这点很重要，因为它避免了 academic_search 再长出第二套 fetch 前置缓存协议。

### 6. 删掉了 github hydrate 这条线和多余的 hydrate 工具

今天按要求把这条支线彻底收掉了：

- `github_hydrate` 相关逻辑
- 旧的 hydrate 工具
- 与之对应的文档页

最终保留的只有 academic_search 下的 OpenAlex 可选水合，不再保留泛化但实际价值不高的老结构。

### 7. 删除了 Serper 支持

搜索 provider 这轮也顺手收了一遍，已经把 Serper 相关支持从代码和接线里移除，避免继续维护一条当前不再需要的 provider 分支。

### 8. 收了一轮 web_search / academic_search 的重复逻辑

今天中间也发现了 web_search 和 academic_search 有一部分重复组装逻辑。

这轮最后的落点是：

这样没有把学术搜索再硬塞回 web_search 内部，但也避免了重复实现继续扩散。

### 11. 把 ranking tokenizer 从混合实现拆成两个显式实现

今天后半段还处理了 ranking engine 里的 tokenizer 问题。

原来是一个混合 tokenizer，把 jieba 和 THULAC 都揉在一起。现在已经改成两个明确实现：

- `JiebaRankingTokenizer`
- `ThuLacRankingTokenizer`

同时：

- 删掉了本地 THUOCL 领域词保护逻辑
- 引入并实际验证了 `thulac`
- registry 显式维护两套 tokenizer
- 当前 engine 默认绑定 `ThuLacRankingTokenizer`

这样 tokenizer 的职责和分流点都更清楚，不再靠一个混合类承担两种策略。

### 13. 统一 XML 渲染层默认过滤 `None`

今天最后还收了一下统一渲染层的输出噪音问题。

之前工具返回结构里如果带很多 `None`，统一 XML 渲染后会出现一堆空标签。这种东西对模型基本没有信息价值，反而会增加阅读负担。

现在统一规则已经改成：

- `dict` 里的 `None` 字段默认过滤
- `list/tuple` 里的 `None` 项默认过滤
- 只有“整个结果本身就是空”的时候，才继续保留空根节点

这样统一渲染层输出会明显更干净。

同时，这件事也把一个边界写得更清楚了：

- 如果某个字段的“空值”真的有特殊语义，就不该再依赖 Python `None`
- 应该由工具显式输出状态字段、明确字符串，或者专门的结构表达

换句话说，`None` 现在默认代表“不值得暴露给模型”。

## 今天做过的重要判断

今天有几个判断值得记一下：

1. 学术搜索应该是显式工具，而不是 web_search 里的隐式 mode。
2. OpenAlex 只能做可选水合，不能参与工具暴露判断。
3. OpenAlex 水合不需要复杂阈值和候选集合，只要按 `url` / `title` 做最小匹配即可。
4. tokenizer 分流应该落在显式类和 registry 上，而不是放在一个混合 tokenizer 的内部开关里。
5. 统一渲染层不该把 `None` 机械转成空 XML 标签；如果 `null` 真有业务语义，必须显式表达。
