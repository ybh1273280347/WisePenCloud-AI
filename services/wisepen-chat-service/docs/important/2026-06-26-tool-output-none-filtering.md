# 2026-06-26 工具输出统一渲染层的 None 过滤

## 背景

在本次调整前，工具返回值只要进入统一 XML 渲染层，`dict`、`list`、dataclass、Pydantic model 中的 `None` 就会被机械保留下来，并继续序列化成空 XML 标签。

这会带来两个问题：

1. **模型可见输出噪音过高**
   - 一个结果对象里如果有很多可选字段，最终会出现大量空标签。
   - 这些标签对模型几乎没有信息价值，只会增加阅读和归纳负担。

2. **“缺省”与“有语义的空值”混淆**
   - Python `None` 本来更接近“当前不暴露 / 当前无值”。
   - 但被统一渲染成空标签后，模型会把它误读为“这个字段被刻意返回了，只是为空”。

这个问题不属于单个工具的局部格式问题，而是统一渲染切面的行为问题，因此需要作为 `important/` 记录。

## 调整内容

本次调整把统一渲染层的默认规则改成：

- `dict` 里的 `None` 字段默认过滤
- `list` / `tuple` 里的 `None` 项默认过滤
- `content_receipt` 渲染同样遵循这套规则
- 只有“整个返回值本身就是 `None`”时，仍保留空根节点

也就是说，`None` 在统一渲染层现在默认代表：

- **不值得暴露给模型**

而不再代表：

- “渲染成一个空标签交给模型自己猜”

## 新的边界约定

这次调整后，统一渲染层与工具实现之间的边界需要按下面理解：

### 1. 缺省值

如果某个字段只是当前没有值、没有必要对模型展示，就继续使用：

- Python `None`

统一渲染层会自动把它过滤掉。

### 2. 有特殊意义的空值

如果某个“空值”本身有业务语义，就不能再依赖 `None`。

必须由工具显式表达，例如：

- 明确的状态字段
- 明确的字符串值
- 专门的结构化对象

换句话说：

- **有语义的 null，应该是工具显式协议的一部分**
- **不是统一渲染层替你保留一个空标签**

## 影响面

### ToolReturn.visible_result

所有走 `ToolReturn.visible_result` 的工具，最终 XML 渲染都会默认过滤内部的 `None`。

这包括但不限于：

- 搜索工具
- 文档工具
- session 工具
- 其他直接返回结构化 `ToolReturn` 的工具

### 普通原生返回值

不是 `ToolReturn`、而是普通 `dict` / `list` / dataclass / Pydantic model 的工具返回值，也会走同样的过滤规则。

### content_receipt

`ToolOutputCache` 在把大文本结果转成 `content_receipt` 时，也会复用这套清洗逻辑。

因此回执里如果以后出现 `None` 字段，也不会再生成空标签。

### error payload

错误输出现在也会走同样的标准化逻辑。

这意味着如果某些错误字段是 `None`，默认不会继续暴露为空标签。

## 预期效果

这次调整的目标不是美化 XML，而是收紧模型可见协议。

预期收益：

1. **模型看到的结构更干净**
   - 不再被大量无意义空标签淹没

2. **协议语义更清楚**
   - 缺省值就是不暴露
   - 真正有语义的空值必须显式表达

3. **统一切面更稳定**
   - 不需要每个工具都自己记得清理 `None`

4. **后续 review 更容易**
   - 如果需要把“空值”暴露给模型，review 时会明确要求解释语义，而不是默认放过

## 后续约束

后面新增或修改工具返回值时，需要遵守这条约束：

- 如果字段为 `None` 且没有显式协议语义，就接受它被统一渲染层过滤
- 如果字段的“空值”必须让模型看见，就不要继续用 `None` 作为表达
