02 / boundaries

先把边界钉住，系统才不会越长越乱。

ID boundary

工具缓存不是知识库 ID

cnt_*、tfile_*、web_content_cache 只服务会话和工具链，不进入长期 RAG 身份体系。

utility boundary

共享组件不背业务职责

chunking_engine 与 ranking_engine 只做基础能力，不承担权限、持久化、抓取或模型输出。

security boundary

检索前过滤，prompt 前硬鉴权

ACL projection 是召回准入；resource-service 的 VIEW hard auth 是进入 prompt 的最后闸门。

03 / retrieval

Elastic 不是补丁，是关键词召回的一等通道。

Qdrant

负责语义相似

  • chunk dense vector
  • 概念解释、同义表达、模糊描述
  • payload ACL filter 必须先执行
  • 只存检索必要字段，不做事实源
Elasticsearch

负责词面锚点

  • 标题、章节、锚点、术语字段 BM25
  • 错误码、版本号、函数名、配置项
  • phrase、must terms、field boost
  • 同样必须带 ACL filter
关键判断 BM25 能承担 lexical relevance；“精确检索”必须靠 must terms、quoted phrases、字段命中和 hard filter 一起完成。

07 / query path

查询时序的核心是：先裁剪，再融合，再注入。

knowledge_search(request, kb_scope) -> validate retrieval_profile and anchors -> build ACL filter from acl_projection -> Qdrant dense search with ACL -> Elasticsearch lexical search with ACL -> application-side RRF fusion -> hydrate child / parent from Mongo -> drop stale / deleted / version-mismatch chunks -> RankingEngine rerank / diversify -> batch VIEW hard auth by resource_id -> Context Builder -> citations + optional cacheable_texts
initial

TopK

Qdrant dense top 80；Elastic lexical top 80；fusion 后候选 100-200。

final

Context

最终 8-20 个 evidence windows，按任务、模型窗口和引用密度动态调整。

08 / graph

图谱是受控扩展层，不是模型的自由游乐场。

default

入库期异步抽取

document version -> chunks -> extraction job -> concept graph。每条边必须回源到 evidence chunk。

query

查询期有限扩展

只从已授权 seed chunks 出发，限制 hop、topK、fanout、budget。

agent

Agent 只触发 job

Agent 可以发现“适合建图”，但不能直接写长期 node / edge。

禁止项 不把 raw graph node id、edge list、全图探索能力默认交给模型；图路径最终必须回到授权 evidence chunks。
09 / generation

第一版不做论文式解码优化，只做证据边界。

required

Context Builder 是唯一入口

  • 只注入已授权 evidence
  • 按 resource_id 做 VIEW hard auth
  • citation 指向原始 evidence_text
not in v1

不采纳的路线

  • 不做 Grounded Decoding
  • 不做 Predictive Prefetching
  • 不把普通 verifier 包装成论文能力

生成质量靠检索边界、证据选择、引用映射和权限硬鉴权兜住，不让论文方案牵动第一版主链。

10 / roadmap

先把主链做稳，再加图谱和事实性增强。

Phase 1
Corpus + 权限投影

KB 文档版本、ACL projection、VIEW hard auth、Qdrant/Elastic filter builder。

Phase 2
双引擎主检索

parent-child chunk、Context Indexing、Qdrant dense、Elastic lexical、profile plan。

Phase 3
Rerank + Tool

Ranking pipeline、parent expansion、citation map、knowledge_search_tool。

Phase 4
Graph + Prefetch

图抽取、受控图扩展、图 evidence 回源和权限过滤；不包含 prefetch 或论文式 grounding。

11 / final rules

记住这 8 条，方案就不会走偏。

  • RAG 是长期业务索引，不是工具缓存。
  • resource_id 是权限根。
  • VIEW 是第一版 RAG 查询权限。
  • Qdrant 做 dense，Elastic 做 lexical。
  • 所有检索都必须先带 ACL filter。
  • Context Builder 是 prompt 注入唯一入口。
  • Agent 不直接写长期图谱。
  • 进入 prompt 的 evidence 必须通过 VIEW hard auth。
定稿：主链稳，旁路轻，权限硬。
